# 02. ユーザーストーリー

形式: 「〈ペルソナ〉として、〈したいこと〉。〈理由〉」＋受け入れ条件。
優先度: **MVP** = 移行切り替えまでに必須 / **後続** = 切り替え後でよい。

## ペルソナ

| ペルソナ | ロール | 状況 | 主な端末 |
|---|---|---|---|
| **喪主（オーナー）** | owner | 香典帳を作り、家族を招待し、最終的に香典返しまで責任を持つ。葬儀前後は多忙で、操作に時間をかけられない | スマホ・PC |
| **家族（編集者）** | editor | 受付の入力、香典返しの手配、住所の整理を手伝う | スマホ・PC |
| **受付の手伝い（編集者）** | editor | 当日だけ受付に立つ親族・知人。招待リンクから初めてログインし、すぐ入力を始める必要がある | スマホ |
| **親族（閲覧者）** | viewer | 誰から何をいただいたか確認したい | スマホ |
| **運営者** | — | サポート対応と事業の状況把握 | PC |

## 全体の流れ

```
葬儀前            当日（通夜・告別式）          〜四十九日                以降
香典帳を作成 ─→ 受付で複数人が同時入力 ─→ 名寄せ・住所整理 ─→ 香典返しを提案・手配・発送 ─→ 一周忌などで見返す
家族を招待       （受付番号を袋に記入）       集計・印刷             リマインドメール
```

## E1 ログイン・アカウント

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E1-1 | 利用者として、Google アカウントだけでログインしたい。パスワードやメール認証の手間をなくすため | Google ボタン 1 つでログイン・新規登録が完了する。初回ログインでアカウントが自動作成される | MVP |
| E1-2 | 旧アプリの利用者として、ログインしたら以前の香典帳がそのまま見えてほしい | 旧アプリで Google ログインしていた人は自動で紐づく。旧アプリでメールログインしていた人も、同じメールアドレスの Google アカウントなら自動で紐づく。紐づかなかった場合は問い合わせ先が案内される | MVP |
| E1-3 | 利用者として、ログアウトしたい / 他の端末のセッションも切りたい | 現在の端末のログアウト、全端末からのログアウトができる | MVP |
| E1-4 | 利用者として、アカウントを削除したい | オーナーである香典帳ごとに「譲渡」か「削除」を選ぶまで削除できない。削除後はメンバー参加もすべて解除される | MVP |
| E1-5 | 利用者として、表示名を変えたい | 変更履歴や編集中表示に使われる名前を変更できる（初期値は Google の表示名） | MVP |

## E2 香典帳と行事

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E2-1 | 喪主として、故人の名前で香典帳を作りたい | 故人名・タイトルを入れて作成すると、既定の行事（「通夜」「告別式」）と既定の関係（親族・友人・会社関係・近所・その他）が用意される | MVP |
| E2-2 | 喪主として、四十九日・一周忌などの行事を後から追加したい | 行事の種類・名前・日付を追加・編集・並べ替え・削除（記録がある行事は削除不可）できる | MVP |
| E2-3 | 利用者として、自分が参加している香典帳の一覧を見たい | 一覧に、香典帳名・自分のロール・件数・合計金額・最終更新が表示される | MVP |
| E2-4 | 喪主として、香典帳をアーカイブ / 削除したい | アーカイブすると一覧の別タブに移り、閲覧のみになる。削除は確認入力つきで、データ・画像が完全に消える | MVP |

## E3 メンバー・招待・譲渡

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E3-1 | 喪主として、招待リンクを LINE で送って家族を参加させたい | ロール（編集者/閲覧者）・有効期限・使用回数上限を指定してリンクと QR コードを発行できる。発行済みリンクを無効化できる | MVP |
| E3-2 | 受付の手伝いとして、リンクを開いたらすぐ入力を始めたい | リンク → Google ログイン → 香典帳の受付画面、の 3 ステップで到達する | MVP |
| E3-3 | 喪主として、メンバーのロール変更・除外をしたい | 一覧からロール変更・除外ができる。除外されたメンバーの WebSocket 接続は即座に切断される | MVP |
| E3-4 | 喪主として、香典帳を別の家族に譲りたい | 既存メンバーを指名すると相手に承諾画面が出る。承諾で入れ替わり、旧オーナーは編集者になる。期限（7 日）切れ・取り消しができる | MVP |
| E3-5 | メンバーとして、自分から香典帳を抜けたい | オーナー以外は自分で退出できる | MVP |

## E4 受付・いただきもの記録

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E4-1 | 受付の手伝いとして、スマホで芳名と金額を素早く登録したい | 必須は「氏名（または団体名）」と、香典の場合の「金額」のみ（金額の要否は E4-3 の種別ごとの条件に従う）。登録すると受付番号が大きく表示され、すぐに次の入力に移れる | MVP |
| E4-2 | 受付の手伝いとして、受付番号を香典袋に書きたい | 番号は行事ごとに 1 から連番で、複数人が同時に入力しても重複しない | MVP |
| E4-3 | 家族として、供物・供花・弔電も同じ台帳に記録したい | 種別（香典/供物/供花/弔電/その他）を選べる。金額は香典のみ必須で、供物・供花・その他は任意（品名・数量を持てる）、弔電は金額なしでメッセージを持てる | MVP |
| E4-4 | 家族として、連名のいただきものを記録したい | 1 件に複数の差出人を紐づけ、それぞれの負担額（任意）を記録できる | MVP |
| E4-5 | 家族として、住所・電話・関係・会社・役職を後から補完したい | PC の一覧画面でキーボード操作で連続編集できる | MVP |
| E4-6 | 家族として、名前・金額・住所で検索・絞り込みしたい | 行事・種別・関係・香典返し状況・金額（範囲）で絞り込み、氏名・カナ・団体・住所で検索できる | MVP |
| E4-7 | 家族として、供物・供花の写真を残したい | 1 件に複数枚の写真を添付できる（R2 に保存、メンバーのみ閲覧可） | 後続 |
| E4-8 | 利用者として、通信が切れたら気づきたい | オフライン時は警告バナーが出て、送信ボタンが無効になる | MVP |

## E5 差出人の名寄せ

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E5-1 | 家族として、同じ人の香典と供花を 1 人にまとめたい | 登録時に既存の差出人を候補表示（氏名・カナの部分一致）して選べる | MVP |
| E5-2 | 家族として、重複登録された差出人を後から統合したい | 2 人を選んで統合すると、いただきもの・香典返しが 1 人に寄る。変更ログに残る | 後続 |
| E5-3 | 喪主として、関係の選択肢を自分たちで追加したい | 関係を追加・名前変更・並べ替え・非表示にできる（使用中のものは削除不可、非表示のみ） | MVP |

## E6 香典返し

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E6-1 | 喪主として、返礼品カタログを登録したい | 品名・分類・価格・画像・説明を登録・並べ替え・無効化できる | MVP |
| E6-2 | 喪主として、「半返し」「3 分の 1 返し」などの金額帯ルールを決めたい | 金額帯（下限〜上限）ごとに返礼の目安率または推奨品を設定できる | MVP |
| E6-3 | 喪主として、ルールに従って全員分の香典返しを一括で提案してほしい | 差出人ごとの合計額から推奨品が提案され、確認して一括確定できる。当日返しの金額を差し引ける | MVP |
| E6-4 | 家族として、香典返しの対応状況を管理したい | 状況（未対応/手配済み/発送済み/当日返し済み/不要）と日付・送付先を記録し、状況別に絞り込める | MVP |
| E6-5 | 喪主として、発送期限が近づいたらメールで知らせてほしい | 行事（四十九日など）の日付から期限を計算し、期限の 14 日前と 3 日前にオーナー（と希望した編集者）へ、未対応件数を含むメールが届く | MVP |

## E7 集計・出力

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E7-1 | 喪主として、合計金額と件数をいつでも見たい | 行事別・種別別・関係別の件数と合計がリアルタイムに更新される | MVP |
| E7-2 | 喪主として、香典帳を紙に印刷したい | A4 の印刷用ページ（芳名一覧・香典返し一覧・宛名一覧）をブラウザで印刷 / PDF 保存できる | MVP |

## E8 共同編集・履歴

| ID | ストーリー | 受け入れ条件 | 優先度 |
|---|---|---|---|
| E8-1 | 喪主として、受付で入力された分がすぐ手元に反映されてほしい | 他のメンバーの登録・修正・削除が数秒以内に一覧と合計に反映される（再読み込み不要） | MVP |
| E8-2 | 家族として、他の人が同じ記録を編集中か知りたい | 「○○さんが編集中」が表示される。閲覧中のメンバー一覧が見える | MVP |
| E8-3 | 家族として、自分の変更が他人の変更を上書きしないでほしい | 開いた後に他の人が更新していた場合、保存時に差分が示され、上書きするか選べる | MVP |
| E8-4 | 喪主として、誰がいつ何を変えたか確認したい | 記録ごとの変更履歴（日時・変更者・変更前後）が見られる | MVP |

## E10 運営者

## 非機能要件

| 区分 | 要件 |
|---|---|
| 性能 | 主要画面の初回表示 TTFB < 300ms（国内）。登録操作の応答 < 500ms。他端末への反映 < 3 秒 |
| 端末 | iOS Safari / Android Chrome の最新 2 バージョン、デスクトップの Chrome / Edge / Safari / Firefox の最新版 |
| アクセシビリティ | キーボードで全操作可能。フォーム要素にラベル。コントラスト比 4.5:1 以上 |
| セキュリティ | 全通信 HTTPS。Cookie は `__Host-` + HttpOnly + Secure + SameSite=Lax。状態を変える要求は Origin 検査。CSP は nonce 方式 |
| 個人情報 | 差出人の個人情報は該当香典帳のメンバーのみが閲覧できる。運営者画面でも中身は表示しない |
| 可用性・復旧 | D1 Time Travel・DO の Point-in-Time Recovery（各 30 日）で復旧可能にする |
